# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

### Features

- *mig lint*: checks every migration against a catalog of lock hazard rules and reports, per finding, the lock mode taken, how long it is held (catalog work, a scan, a table rewrite, an index build) and what that blocks, because mode times duration is the hazard: *ACCESS EXCLUSIVE* held for catalog work is routine and the same lock held for a rewrite is an outage. Offline is the default and touches no database. Exit code is non-zero only when a finding is an error, so warnings can be read without failing a build.

- The lock model behind the rules is validated against live servers rather than transcribed from documentation. A test matrix runs every predicted statement against seeded tables on Postgres 17 and 18 and reads back what actually happened: locks from *pg_locks*, where a waiting request is observed the same way as a granted one; rewrites from *pg_class.relfilenode* changing; scans from the server's own *client_min_messages=debug1* account of the relations it visited; and the in-transaction refusal by expecting SQLSTATE 25001. Implicit locks are resolved: a foreign key locks the referenced table, DDL locks dependent views, a type change rebuilds every index on the column.

- Twenty-four rules, *L001* to *L042*: rewrites and long locks (*CREATE INDEX* without *CONCURRENTLY*, a rewriting *ADD COLUMN* default, *ALTER COLUMN TYPE*, *SET NOT NULL* without a proving validated *CHECK*, constraints added without *NOT VALID*, *ADD PRIMARY KEY* without *USING INDEX*, *VACUUM FULL* and *CLUSTER*); transaction and ordering hazards read from the whole step, since a transactional step holds its locks to the commit (several *ACCESS EXCLUSIVE* statements in one transaction, row work sharing a transaction with other DDL, an index built before the backfill that fills it, an enum value used in the transaction that added it, a blocking step with *no_lock_timeout*); application coupling (drops, renames, a table created and never granted to the application role, *TRUNCATE*); and data volume (unbounded *UPDATE* and *DELETE*, a concurrent index build reconciled by a hand-written predicate that never checks *indisvalid*). Version-conditional behaviour follows *--target-version*: a non-volatile default stops rewriting at 11, a validated check lets *SET NOT NULL* skip its scan at 12. **No rule reports an O(rows) hazard against a table the same migration creates before the statement runs**, because that table is empty when the statement executes, and create-then-index in one file is the most common migration shape there is.

- Connected mode. With *--dsn* the linter reads the catalog and grades each size-dependent hazard by the table it names: an error at a million rows or a gigabyte, an observation below ten thousand rows and eight megabytes, a warning between, and always a warning offline where nothing knows the size. Findings carry the size they were graded on and an estimate of how long the work will hold its lock, from a calibration probe run once per connection: a 200,000-row table built and rolled back, timed for a rewrite and an index build, measuring both bytes and rows per second so narrow rows do not read as fast ones. A read-only standby refuses the probe; the findings and sizes still report and the run says why the estimates are missing. The target version becomes the server's own.

- *mig lint --fix*: rewrites flagged statements as safe steps in mig's own format, after showing the diff and asking; *--yes* skips the question for CI. Fixes are built as parse trees and deparsed, never assembled as text. A rewriting *ADD COLUMN* becomes add-nullable, set-default, batched backfill, *NOT VALID* check, *VALIDATE*, *SET NOT NULL*; constraints become the two-step *NOT VALID* then *VALIDATE* pattern; a primary key becomes a concurrent unique index then *ADD CONSTRAINT ... USING INDEX*. Where a safe rewrite needs a change the linter cannot make, a column type swap needing the application to dual-write across a deploy, the fix is a scaffold: fully commented out, inserted above the statement rather than replacing it, with a TODO naming the application change. **Every executable fix is held to the executor rather than to an eyeball**: the fixed migration must produce a schema fingerprint identical to the unsafe statement it replaced, and must lint clean afterwards. With *--dsn* a generated backfill pages by the table's real primary key instead of assuming *id*.

- Output formats. *--format human* prints the offending line with a caret under it, the lock detail and the estimate. *--format json* emits one object for scripting. *--format sarif* writes a SARIF 2.1.0 log for GitHub code scanning, which annotates the changed lines of a pull request, with each finding's file named relative to the migration directory so the annotation lands on the diff. *--format github* renders one pull-request comment: a table of file, rule, severity, what happens, the lock and the estimate, and a clean run renders "no lock hazards found" rather than nothing, because the comment replaces the previous one and silence would leave a stale verdict standing.

- Policy file. *.miglint.yaml* beside the command, or *--policy* naming another path, assigns per-rule severities (*off*, *info*, *warn*, *error*), moves the four size thresholds, names a target version, and overrides severities per migration directory for a repository holding several. An unknown field is an error rather than a line quietly skipped, for the same reason an unknown annotation is: a misspelled setting the author believes is in force is worse than none. Precedence for the target version is the flag, then the policy, then the default, and *--dsn* outranks all three.

- Suppressions. *-- +mig lint:ignore <rule> reason="..."* silences one rule over the step it sits in, or over the file when it stands above the first *step:* line. **The reason is mandatory**: a directive without one, or naming a rule the build does not have, is itself an error finding under *L000*, reported after suppression runs so a broken suppression cannot silence the complaint about itself, and *L000* can be neither turned off by policy nor named in a directive. The directive is an annotation rather than a plain comment, so adding one to an applied migration leaves the step's checksum alone and is not reported as drift. *--report-suppressions* lists every directive with its rule, reason, age taken from the migration's timestamp version, and whether it still silences anything, so suppressions are audited rather than accumulating forever.

- *mig lint verify*: measures what static analysis predicts. It applies the migrations to a throwaway database it creates and drops on a server named by *--dsn*, under traffic described by a workload file, and reports client-side latency percentiles before and during (p50, p99, p999, max), the blocked-query count, the longest block and its relation, and server-side wait attribution sampled from *pg_stat_activity*, which turns "queries got slow" into "queries waited on Lock:relation". *--budget p99=50ms,max_block=2s* makes it a gate: any term exceeded exits non-zero. **The workload must include a long-running reader and is refused without one**, because the production catastrophe is rarely the DDL itself: it is the DDL queueing behind a slow query and, since Postgres grants locks in order, blocking everything that arrives after it. The workload and the migration run on separate connection pools, since pool exhaustion masquerades as lock contention. The binary carries no container dependency; tests still provision Postgres through the harness.

- *pkg/mig* grows the same surface: `Lint`, `LintConnected`, `LoadPolicy`, `Chaos`, `ParseWorkload`, `ParseBudget` and `RenderChaos`, with `LintReport` carrying the findings, sources, suppressions and the calibration outcome, so a project can run the linter from a Go test rather than a shell.

### Fixed

- The executor repairs before every retry, not only on a fresh run. A *CREATE INDEX CONCURRENTLY* cancelled by the lock timeout leaves an invalid index, and the retry inside the same run reran the statement against it and failed with "already exists", so the step could never converge while the run lived. Found by running migrations under the verify harness's workload, which cancels statements while the process survives; the kill matrices, which kill the process, cannot reach it.

## v0.1.0 - 2026-07-31

### Features

- *mig up*: applies a directory of annotated SQL and converges on it. Ordered by a zero-padded timestamp in the file name, one lease per run, one pinned connection per step. A machine-readable summary goes to stdout and structured logs to stderr, so the two never interleave. Exit codes distinguish a failure from another runner holding the lease.

- The command line is a [cobra](https://github.com/spf13/cobra) command tree, with *--help* per command, *--version*, and shell completion.

- A progress display. `mig up` shows each step as it runs: its number in the plan, a live spinner with elapsed time on a terminal, what a repair found, where a backfill resumed, and a mark with the duration when it finishes. Steps the catalog already shows as done display nothing, so a converged run is silent. The display goes to stderr and animates only on a terminal; anywhere else lines are only appended, so a CI log stays readable. stdout still carries exactly the machine-readable summary. `--verbose` replaces the display with structured JSON logs carrying the same records.

- The executor reports every step transition through its logger: announced when there is work, closed whatever the outcome, with its position in the plan, status, attempts and duration. A backfill also reports the checkpoint it resumed from. A library caller who passes a logger in `Options.Log` gets the same records.

- Transactional DDL steps. A step without a *notx* annotation runs inside a transaction the executor opens, and its ledger row is written in that same transaction: the fence is asserted first, the DDL runs, the row is written, and one commit covers all three. A run killed part-way through leaves the ledger exactly as it was, so unlike a concurrent index build there is nothing to reconcile and no repair or postcondition check to perform. It is also the one place the ledger is allowed to decide whether work remains: a row saying *succeeded* committed with the DDL it describes, which is what lets a statement carrying no inferable predicate be skipped on the next run rather than reapplied.

- Backfill steps. A *backfill:* annotation naming *table*, *key* and optionally *batch* and *max_lag_bytes* turns a statement into a resumable one, with *:cursor_lo* and *:cursor_hi* marking the key range each batch covers. Pagination is by key range only: *OFFSET* rescans everything it skips, so its cost grows with the square of the table, and it silently misses rows when concurrent writes shift what it is counting past. **Each batch commits with the cursor that covers it, in one transaction.** An index build cannot be made atomic with its ledger row and so has to be reconciled; a batch and its cursor can be, so "the rows landed but the cursor did not" is structurally impossible rather than merely unlikely. A backfill requires a *satisfied:* predicate, since the cursor lives in the ledger and the ledger may not decide whether work remains.

- *internal/throttle*: closed-loop pacing. Batch size halves when replication lag passes *max_lag_bytes* or a batch runs longer than the target, and grows back by a quarter when neither does, clamped between 100 and 50,000 rows. Lag comes from *pg_stat_replication*; a primary with no replicas reports none rather than failing. Batches run on their own connection pool so a backfill cannot starve the heartbeat that keeps its lease alive.

- Predicate inference covers every statement the design lists. *ALTER TABLE ADD COLUMN* and *DROP COLUMN* are judged by the column's presence, with a dropped column read from *attisdropped* rather than by name, since Postgres keeps the row and marks it. *ADD CONSTRAINT* is judged by the constraint existing and *VALIDATE CONSTRAINT* by *convalidated*, which is the distinction the two-step pattern depends on: a constraint added *NOT VALID* exists and is not validated. *CREATE TABLE* is judged by the relation existing and *ALTER TYPE ADD VALUE* by the label being present. A step is satisfied only when all of its statements are. Names resolve through *to_regclass* and *to_regtype*, exactly as the statement that created them would resolve them.

- *mig plan*: prints every step, its kind, and the condition the catalog must satisfy for it to count as done. It opens no connection and writes nothing, so the refusal a run would make is visible before a database is involved; a directory containing a step that cannot be reconciled is shown and reported through the exit code. The description comes from the same switch as the predicate, so what is printed and what is evaluated cannot drift apart.

- *mig verify*: reports whether the database shows every migration. It takes no lease and writes nothing, which is what makes it safe to run from every replica at once. Applying on boot from the service binary is the shape it exists to replace: every replica races, none is elected, and a slow migration collides with the readiness probe. Exit 0 when nothing is outstanding, 3 when something is, 1 when the check itself failed, because a scheduler treats "not migrated yet" and "could not tell" differently. Checking stops at the first outstanding step: everything after it is outstanding by definition, and evaluating a later predicate would fail against a column an earlier step has yet to create.

- *mig status*: prints what the ledger records for every step (state, attempts, checkpoint, last error) as a table or as JSON. Those are the things a catalog cannot report, which is the only reason to read the ledger at all. A database no run has touched has no ledger, which is nothing recorded rather than a failure.

- *mig import --from goose|golang-migrate*: adopts a history written by another tool. Everything that tool applied is recorded as succeeded so it is not applied again; everything else is left to reconcile against the catalog, which is safe whether or not it in fact ran. No file is rewritten and no schema is touched. Each migration is adopted in its own transaction, so an import that fails part way still reports exactly what landed, which is what tells the operator where a re-run resumes. The two histories are read as what they are rather than converted into one another: goose keeps a row per apply and per rollback, so a rolled-back migration is correctly outstanding, while golang-migrate keeps only a high-water mark. Its *dirty* flag, which stops every deployment there until a human clears it by hand, is reported, and the version it names is left for the catalog to settle. A version applied there with no file here is named rather than refused, since files get deleted once everyone has deployed past them.

- *mig fingerprint*: prints the canonical schema digest, or with *--describe* the rows it is taken over.

- A migration file may carry any number of leading digits, and ordering is by the version as a number rather than as text, so an adopted history counting from 1 sorts where it belongs rather than where its digits fall. A golang-migrate directory loads unchanged: *.down.sql* files are skipped and the *.up* suffix is trimmed from the identifier, since loading both files of a pair would read them as two migrations claiming one version and refuse the whole directory.

- *pkg/mig*, the library the command line is built on. `Up`, `Verify`, `Pending`, `Status`, `Plan`, `Import`, `Fingerprint` and `Describe` take a `*sql.DB` and an `fs.FS`, so a program migrates without shelling out to a binary and a service embeds its migrations with *go:embed* rather than shipping a directory beside itself. Every command is a thin wrapper over this package, which is what keeps the binary and the library from drifting apart. The two halves are meant for different places: applying is a job holding a lease, checking is what a service does as it starts.

- *internal/exec*: the executor. Before anything else it asks the catalog whether the step's work is already present, unconditionally rather than when the ledger looks suspicious, and skips the step if so. Only then does it consult the ledger, and only to decide whether an earlier attempt left the database part-way through and needs repairing first. Attempts are recorded before the work starts, so a crash during the work leaves evidence. After the work it re-checks the predicate: a step that reports success without changing the catalog fails rather than being recorded as done.

- *internal/step*: the *Step* and *NoTxStep* interfaces, and *DDLNoTx*. A non-transactional step cannot commit its ledger row with its work, so it carries a predicate that recognizes finished work in the catalog and a *Repair* that clears a partial one. *Repair* drops an index left invalid by an interrupted concurrent build (Postgres will not resume one) and is itself re-entrant, using *IF EXISTS* and re-reading the catalog rather than trusting a previous call. Constructing a non-transactional step without a predicate fails with *ErrNoPredicate*.

- *internal/parse*: statement classification through the real Postgres grammar, so quoted identifiers, embedded comments, partial indexes and multi-line statements are read as the server reads them. *Checksum* hashes the statement's fingerprint rather than its text, so reformatting a migration or editing its comments does not register as drift while a changed index, table, column or *UNIQUE* does.

- *internal/predicate*: inference from parsed SQL. *CREATE INDEX* is satisfied when the index exists and is both valid and ready; *DROP INDEX* when it is gone. A step is satisfied only when all of its statements are, and one unclassified statement makes the whole step uninferable. *SQL* provides the *satisfied: sql(...)* escape hatch.

- *internal/plan*: reads annotated SQL into ordered steps. Annotations: *step:*, *notx*, *satisfied:* and *no_lock_timeout*. SQL before the first *step:* becomes an implicit step, so an unannotated file is a valid single-step migration. Duplicate versions, duplicate step names, unknown annotations and empty steps are rejected at load.

- *internal/catalog*: index introspection resolved through *to_regclass*, so a name is looked up exactly as the statement that created it would resolve it. *Fingerprint* hashes columns, indexes (with *indisvalid* and *indisready*), constraints (with *convalidated*), sequences, ownership and grants into a canonical form; *Describe* returns the same content readably so a mismatch can be diffed. System schemas are excluded, since TOAST index names embed the OID of the table they serve.

- *internal/session*: pinned-connection setup. Session state on a pooled handle is meaningless, so every step runs on its own *sql.Conn*. *DetectPooling* probes for a transaction-pooling pooler in two round trips and refuses to run behind one rather than working around it. *WithLockRetry* retries only *55P03*, backing off from one second with jitter.

- *internal/ledger*: the ledger schema and the fenced write path. *EnsureSchema* creates schema *mig* with the *migrations*, *steps*, *lease* and *lease_expiry* tables, and is safe to call from several runners at once: it holds *pg_advisory_xact_lock* for the duration, because *CREATE ... IF NOT EXISTS* still lets two simultaneous creators collide on the catalog's unique index. Lease ownership and expiry are separate rows on purpose: every ledger write locks the ownership row for the length of its transaction, and a backfill's transaction lasts as long as its batch, so with both in one row renewal would queue behind the batch and the holder would give up a lease it still owned. Every mutation goes through *Write* or *Guard*, each of which begins with *SELECT ... FOR UPDATE* on the ownership row and returns *ErrFenced* when the caller's token no longer matches. *Guard* is exported separately for the writes that must ride in a caller-owned transaction: a transactional DDL step commits its ledger row with its DDL, and a backfill batch commits its cursor with the rows it covers. Ledger transactions are pinned to Read Committed rather than inheriting *default_transaction_isolation*, since under a snapshot isolation level *SELECT ... FOR UPDATE* against a row a successor has already updated aborts with a serialisation failure instead of returning no rows, reporting a final *ErrFenced* as a retryable error. Row helpers: *UpsertMigration*, *SetMigrationStatus*, *LoadMigration*.

- *internal/lease*: lease acquisition with a monotonic fence token. *Acquire* takes the lease when it is free or expired and increments *fence*, judging expiry by the server's clock so runners with disagreeing clocks still agree on whether a lease has lapsed; it locks ownership and expiry together, so a waiter cannot pair a new owner with a stale expiry and take a lease someone else holds. *Config.OnLocked* selects *Wait* or *Fail*, and an empty *Config.Owner* is rejected with *ErrNoOwner*. *Keepalive* renews at TTL/3 and returns a context cancelled with *ErrLost* as its cause, so losing the lease aborts the work rather than being logged; every renewal attempt is bounded by the heartbeat interval, so it gives up while validity remains, never after expiry, even when a lost route leaves a renewal that would otherwise wait forever. *Release* is itself fenced and bounded by the TTL, so a superseded runner cannot hand away a lease its successor is using and a partitioned one exits instead of hanging. *NewOwner* combines host, pid and a random suffix.

- *internal/crash*: named fault injection points armed by *MIG_CRASH_AT*. They are compiled into the shipping binary and gated on the environment rather than a build tag, so the tested program is the one that ships, and they terminate with SIGKILL so no deferred function runs and no buffered write lands.

- *test/harness*: Postgres and process control for the recovery tests. One container per test package, with per-test isolation by cloning a seeded template database rather than re-seeding. *Build* and *Start* spawn the runner under test as a real child process in its own process group, with *Kill*, *Freeze* and *Thaw* for SIGKILL, SIGSTOP and SIGCONT. *WaitBackendsGone* blocks until a killed child's server-side backend has actually disappeared, and the container sets *client_connection_check_interval=100ms*: without it a backend only notices its client died on its next socket write, so one blocked in a long *CREATE INDEX CONCURRENTLY* outlives the kill and finishes the index.

- Recovery tests over the migrator as a spawned process, covering each point at which it can die during a concurrent index build: before the lease, after the lease, once recorded as running, before the DDL, after the DDL commits but before the ledger write, after the step succeeds, during an interrupted build, and inside the repair itself. Each asserts a schema and data fingerprint equal to an uninterrupted run, no invalid indexes or unvalidated constraints, no lease still held, and, the assertion that catches a migrator which reapplies its work forever, that a further run applies and repairs nothing.

- *test/kill*: recovery tests over spawned processes. Several runners starting together admit exactly one, with the rest exiting cleanly and the fence advancing once; a waiting runner starts only after the first has finished, checked against the server's clock. A runner frozen with SIGSTOP past its lease expiry, resumed after a successor has taken over, is rejected by the fence, exits non-zero, and leaves its ledger row untouched. A runner killed mid-work does not lock the database out.

- Partition tests. A TCP proxy in the test harness stops delivering in both directions while leaving every socket open, which is what a lost route looks like from inside a process that is otherwise healthy. Every other recovery test kills the runner, and a killed runner stops by definition; a partitioned one is healthy and has to decide to stop. Both levels are covered: the heartbeat gives up and cancels the work while the lease is still valid, and the process exits rather than waiting on a socket nobody will answer. The run it leaves behind converges like any other, with the same assertion bundle.

- A seeded fuzz over kill timing. It kills at a moment nobody chose, which is the only way to reach the cases nobody thought of, and every iteration derives its delay from a seed the output prints, so a failure replays exactly with *MIG_FUZZ_SEED*. Three iterations run on every push; a nightly workflow runs 500 against each Postgres version.

- The recovery matrices run against two Postgres majors. Recovery behaviour for a concurrently-built index is version-sensitive, so passing on one proves less than it appears to. The harness reads *MIG_PG_IMAGE*, so any package can be pointed at another major without editing anything, and the default is *postgres:18-alpine*.

- *test/faultdb*: a *database/sql* driver that fails a chosen statement, matched by a substring of its SQL. The kill matrices cover a process dying between operations; this covers one failing at the instant it runs: a commit refused, a rollback that does not land, a row that will not scan. A faulted commit rolls back rather than being skipped, which is what a failing commit really does, so the transaction cannot sit holding locks nobody will release.

- *Makefile*: *make cover* merges two coverage sources. Parent test binaries report through *-coverprofile*; binaries spawned as children are built with *-cover* and report into *MIG_COVERDIR*. Counting only the first would report the migrator, which only ever executes in a child process, as untested.
